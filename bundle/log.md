
# Change log & provenance

## 2026-08-10

* **Profile provenance**: Vendored the complete 16-file Explorer v0.6.0 Bundle
  Wiki profile byte for byte with its adjacent release lock. The producer
  verifier checks the exact inventory, profile-subtree identity, per-file and
  aggregate digests, schema identity and safe local installation paths.
* **Fail-closed validation**: Added bounded, non-symlink Markdown and YAML-LD
  reads; rejected aliases, excessive structure and assertion-local JSON-LD
  controls; and reused the verified in-memory relationship schema throughout
  validation and receipt generation.
* **Publication closure**: The static build now rejects undeclared, hidden,
  non-regular or self-checksummed extra files. Its reviewed node and
  relationship baselines live in configuration rather than executable
  validator constants, and all source and generated bytes are checked against
  one deterministic manifest.
* **Editorial standard**: Standardised producer-authored prose on British
  English and generated HTML on `en-GB`, while preserving exact governed
  identifiers, official titles and immutable profile bytes.

## 2026-08-09

* **Semantic identity**: Added the pinned Bundle Wiki context, absolute `@id`
  and `okf:Concept` type to all 142 production concepts. Reserved indexes and
  logs retain their OKF 0.2 navigation form and receive projection-only IDs.
* **Relationships**: The 579 authored local Markdown links now use the exact
  `normalized` status and are emitted conservatively as directed
  `dcterms:references` relationships. No domain
  predicate is inferred from prose, section or link position.
* **Projection**: YAML-LD and JSON-LD now contain 155 route-bearing entities,
  579 direct triples and 579 matching evidence-bearing
  `okf:RelationshipAssertion` nodes. Explorer JSON and `relationships.json`
  preserve the same routes, IRIs, provenance, evidence, rights and direction.
* **Validation**: Added pinned semantic-context expansion, relationship schema,
  deterministic ID/evidence tests and direct/reified/runtime reconciliation.
* **Authoring**: Added explicit front matter `assertions` for evidence-backed
  domain predicates; the compiler rejects unresolved routes, IRI mismatches and
  duplicate triples.

## 2026-07-25

* **Format**: Migrated canonical Markdown to Open Knowledge Format v0.2. The root alone declares `okf_version`; directory indexes and the log use reserved-file form without concept front matter.
* **Provenance**: Replaced source-oriented legacy timestamps with `sources[].last_modified` where a reviewed resource exists. Actor-free `verified: "yes"` flags were not promoted into v0.2 verification events, avoiding an unsupported human-review claim.
* **Compatibility**: Explorer and legacy-viewer projections synthesise navigation nodes and preserve tags, aliases, routes and unknown producer extensions while publishing structured v0.2 metadata.

## 2026-07-07

* **Update**: Applied the Claude Fable 5 code review: XSS and URL-scheme hardening across the Svelte, static, and legacy viewers; harvested-URL sanitisation (credential redaction, scheme validation) and data-hygiene warnings in the UK Government API generator; CI now exercises the generator against fixtures. Full findings in `docs/code-review-2026-07-07.md`.
* **Update**: Restructured this log to OKF §7 date-grouped headings; intentional OKF v0.1 deviations documented in `docs/okf-conformance.md`.
